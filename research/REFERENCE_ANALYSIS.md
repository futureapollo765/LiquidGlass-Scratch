# Scratch reference analysis

Sources read without changes:

- `reference_1.json`: Liquid Glass V1.7.sb3, 625 blocks across Stage / Render / Scanner; only Pen extension.
- `reference_2.json`: Liquid Glass v5 - Still Not Done.sb3, 901 entries on liquid glass; only Pen extension.
- `reference_3.json`: Liquid Glass v7.sb3, 1669 entries on liquid glass; only Pen extension.

The corresponding `.txt` files are readable block-tree dumps, generated by `dump_blocks.py`. They are reference documentation; runtime code remains Scratch blocks.

## Directly reusable shape formulas

V1.7 uses full width and height. Its Render custom blocks implement:

```
circle: sqrt((x-cx)^2 + (y-cy)^2) - radius
qx = abs(x-cx) - (width/2 - radius)
qy = abs(y-cy) - (height/2 - radius)
roundedRect = sqrt(max(qx,0)^2 + max(qy,0)^2)
              + min(max(qx,qy),0) - radius
capsule: roundedRect with radius=min(width,height)/2
```

Use the rounded-rectangle formula as the common shape family. A circle is width=height=2*radius with corner radius=radius; a capsule uses half the smaller dimension; a rounded rectangle independently controls its corner radius. Interpolating width, height and clamped radius is a continuous geometric transition without switching distance algorithms. Scratch's `abs`, `sqrt`, comparison, multiply, subtract and add blocks suffice. `min`/`max` are custom blocks or conditional assignments in these projects; there is no standard Scratch min/max reporter.

V7's `apply_rect x y w h r` uses **half extents** `w` and `h`, despite its short names. Do not copy its dimensions into V1.7's full-dimension interface unchanged. It clamps render bbox bounds to the 480×360 stage and multiplies coordinates/radii by `1/quality`, where quality is the pixel stride.

## Metaball implementation and its limitation

All references use the same polynomial smooth minimum, in equivalent forms:

```
h=max(k-abs(a-b),0)
d=min(a,b)-h*h/(4*k)
```

or

```
h=clamp(0.5+0.5*(b-a)/k,0,1)
d=a*h + b*(1-h) - k*h*(1-h)
```

V1.7 safely bypasses smoothing when k=0; V5 and V7 divide by k without a similarly obvious dedicated zero branch. Guard it in the new renderer.

The subtraction is nonnegative and enlarges a union wherever the distance fields are close. An isolated shape is unchanged, and locations with `abs(a-b)>=k` are unchanged. Near coincident or broadly overlapping shapes, however, equal distance fields can enlarge the whole perimeter by up to k/4 for a pair; iterative accumulation can compound this. Therefore **copying this formula unmodified does not satisfy the user's no-global-inflation requirement**. Restrict smooth merging to a spatially local facing region / bridge, preserve the original far outlines, and test coincident/overlap cases as well as separated shapes. A generic support-envelope clamp can prevent bounds inflation but must also be checked for kinks where the clamp meets the blend.

## Drag and transitions

None of the three inspected projects implements actual drag deformation or stateful shape transitions.

- V1.7 records a shape under the mouse when not held; on mouse-down it replaces x/y with the mouse's exact x/y. It neither preserves the grab offset nor deforms the shape.
- V5 creates three fixed circles and one circle centered exactly at the mouse each frame.
- V7 similarly builds a mouse-following circle or rounded rectangle, plus two sinusoidally moving circles depending on demo mode. It updates geometry directly.

The new project therefore needs its own Scratch-block state for target geometry, current geometry, pointer grab offset, spring/lag displacement and recovery. The shape SDF can be evaluated after a smooth nonlinear inverse coordinate warp along the drag vector; changing width/height alone would not meet the request. Apply the same deformed SDF to both the mask and its normal calculation, so optical highlights/refraction follow the pulled contour.

## Rendering facts worth retaining

V1.7 samples the backdrop using a Scanner sprite, stores RGB maps, computes finite-difference normals from a full-stage signed distance map, and distorts near the border. Its `t=1-abs(distance)/edgeThickness`, displacement `normal*t^3*Distortion` is distinct from the V5/V7 refraction model. The EffOnly project should control the new renderer's optical model as requested.

V5/V7 sample RGB lists bilinearly. Pen packed color order is `red*65536 + green*256 + blue`, while V1.7's map names come from the opposite extraction naming but reconstruct the original packed color consistently. Preserve actual channels when changing libraries.

V7 adds useful optimizations:

- Distance fields only update expanded object bounding boxes.
- Static distance/color buffers are copied, and prior dynamic regions restored.
- Only touched regions are shaded; a per-frame mark list avoids duplicate shading.
- Adjacent similar colors are combined into horizontal pen runs using `merge_tol`.
- Change signatures skip full redraws when scene/material parameters are unchanged.
- Interior pixels beyond optical edge thickness use the preblurred background directly.

V7's `shade` appears to retain refraction, dispersion, blur and tint but does **not** apply its retained `f_*` / `g_*` highlight variables in the final shading chain. Using it as the material reference would therefore lose some desired controls. EffOnly remains the better base.

## SB3 structure observations

Use only genuine core and Pen opcodes. Existing projects show procedure definition→shadow prototype, prototype mutations containing matching `proccode`, JSON-encoded `argumentids`, `argumentnames`, `argumentdefaults`, and `warp`. Calls reference the matching argument IDs in `inputs` and matching `proccode`/`argumentids` mutation data. Argument reporters have `fields.VALUE=[argumentName,null]`. Data list/variable fields carry both display name and ID. Nested stacks and reporter blocks require correct `parent`, `next`, and `topLevel` links. The project can be generated externally as ZIP/JSON, but all runtime logic must be these standard Scratch blocks.
